# OmniFlow Runbook: Product Feedback & Feature Requests

**Category:** `feature_request`  
**Applies to:** New integrations, unsupported triggers, UI/UX improvements

## Triage & Logging Workflow
1. **Check Existing Roadmap:**
   - Search the public roadmap (`feedback.omniflow.internal`) to determine if the requested capability is Planned, In Development, or Under Review.
   - If an existing entry exists, share the URL so the customer can upvote and subscribe to releases.

2. **Logging New Requests:**
   - Direct the user to submit details to the product board or log it internally via the Product Feedback tag.
   - Capture:
     - Specific third-party tool and API version.
     - Concrete business impact / workflow blocked.
     - Customer plan tier and ARR.

3. **Setting Expectations:**
   - Explicitly decline committing to delivery timelines or release dates.
   - Clarify that feature requests do not receive SLA tracking or active engineering dispatch.

## Escalation Criteria
- Contractually negotiated custom features for Enterprise accounts with ARR > $50k: Route ticket directly to the assigned Account Executive with priority `LOW`.
